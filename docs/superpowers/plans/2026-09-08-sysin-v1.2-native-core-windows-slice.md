# SysIn V1.2 Native Core + Windows x64 Vertical Slice Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the first native SysIn preview as a side-by-side Windows x64 vertical slice proving the universal telemetry contracts, supervised collectors, immutable snapshots, purpose-built responsive Spectrum TUI, real local Overview telemetry, and basic CLI/JSON without replacing or modifying the installed V1.1 runtime.

**Architecture:** The slice creates a .NET 10 native application beside the existing PowerShell runtime. Windows-specific collectors translate real system data into universal typed observations; the telemetry store produces coherent snapshots; CLI and the TUI consume those snapshots through separate presentation layers. The TUI uses a virtual-testable framebuffer/diff renderer and responsive Spectrum components. V1.1 files and tests remain intact throughout this plan.

**Tech Stack:** C# 14 / .NET 10 LTS; `xunit.v3` 4.0.0; `Microsoft.NET.Test.Sdk` 18.9.0; `System.Management` 10.0.12 for Windows GPU identity discovery; `System.Diagnostics.PerformanceCounter` 10.0.11 only where Windows performance-counter telemetry is explicitly used; built-in `System.Net.NetworkInformation`, `System.IO.DriveInfo`, and P/Invoke for low-cost Windows CPU/memory primitives.

**Spec:** `docs/superpowers/specs/2026-09-08-sysin-v1.2-universal-mesh-design.md`

## Global Constraints

- V1.1 PowerShell files, launcher, installer, manifest, and existing PowerShell tests remain unchanged in this workstream.
- The preview executable is invoked explicitly from its build/publish output; this plan does not replace the installed `sysin` command.
- Target framework is `net10.0`; Windows-only provider code is isolated in `SysIn.Platform.Windows`.
- Native projects enable nullable reference types, implicit usings, deterministic builds, and warnings as errors.
- No UI/view code may directly invoke Windows/provider APIs.
- Unknown/unsupported/unavailable metrics are represented explicitly and never as numeric zero placeholders.
- Every physical/logical device has a stable internal `DeviceId`; human names are separate metadata.
- Render target and telemetry sampling are independent. Balanced preview target is 20 FPS; actual FPS is measured.
- No busy-wait loops.
- No administrator requirement for the preview.
- No account, Mesh, cloud telemetry, service, scheduled task, PATH mutation, installer replacement, or V1.1 migration occurs in this workstream.
- No destructive process/system controls occur in this workstream.
- The Overview must use the locked Spectrum subsystem identity and responsive modes; a tiny upper-left dashboard or huge unexplained dead space is a HOLD.
- GPU identity is required in this slice. GPU utilization is displayed only when a trustworthy Windows counter can be mapped to a discovered GPU; otherwise the affected utilization is explicit `N/A` rather than guessed.
- This workstream ends at a Preview/HOLD-or-PASS gate. It does not authorize Stable or a GitHub Release.

- [ ] **Step 3: Implement bounded collection execution**

Use a linked CTS per collection attempt:

```csharp
using var timeout = CancellationTokenSource.CreateLinkedTokenSource(cancellationToken);
timeout.CancelAfter(collector.Timeout);
var started = timeProvider.GetTimestamp();
try
{
    var observations = await collector.CollectAsync(timeout.Token);
    store.Publish(observations);
    MarkSuccess(collector.Id, timeProvider.GetElapsedTime(started));
    return CollectorRunResult.Success(observations.Count);
}
catch (OperationCanceledException) when (!cancellationToken.IsCancellationRequested)
{
    MarkFailure(collector.Id, "Timeout", timeProvider.GetElapsedTime(started));
    return CollectorRunResult.Failure("Timeout");
}
catch (Exception ex)
{
    MarkFailure(collector.Id, ex.GetType().Name, timeProvider.GetElapsedTime(started));
    return CollectorRunResult.Failure(ex.GetType().Name);
}
```

Do not store full exception text/stack in `CollectorHealth`; diagnostic logging comes in a later workstream. Preserve only safe error class/state here.

- [ ] **Step 3: Implement CPU/memory/system primitives**

CPU uses `GetSystemTimes` deltas. Keep previous idle/kernel/user counters; first collection returns `Unavailable` for `cpu.utilization` because a delta does not yet exist. Subsequent collections compute:

```text
busy = (kernelDelta + userDelta) - idleDelta
utilization = clamp(100 * busy / (kernelDelta + userDelta), 0, 100)
```

Memory uses `GlobalMemoryStatusEx` and emits used, available, and utilization. Uptime uses `Environment.TickCount64 / 1000.0` as `system.uptime` seconds.

- [ ] **Step 4: Implement device discovery and rate collectors**

GPU identity uses `System.Management` with:

```sql
SELECT PNPDeviceID, Name, AdapterRAM, DriverVersion, VideoProcessor FROM Win32_VideoController
```

Create opaque GPU IDs from `PNPDeviceID` when present; otherwise from stable available identity parts. Never use WMI enumeration order as identity.

`WindowsGpuUsageCollector` may read `GPU Engine` performance counters. Only attach utilization to a discovered GPU if the counter instance's LUID/physical identity can be mapped deterministically to that GPU. If mapping cannot be proven, emit `gpu.utilization = Unsupported` for that device in this slice; do not assign a counter by list position.

Network uses `NetworkInterface.GetAllNetworkInterfaces()` and `GetIPv4Statistics()` byte counters. First sample has no rate; second sample emits `(deltaBytes / deltaSeconds)` for receive/transmit. Do not expose MAC/IP/SSID in the Overview model.

Volumes use `DriveInfo.GetDrives()` and register `DeviceKind.Volume`; emit capacity and used bytes only for ready fixed/local volumes. Do not call a logical volume a physical disk.

await terminal.EnterInteractiveAsync(cancellationToken);

}
