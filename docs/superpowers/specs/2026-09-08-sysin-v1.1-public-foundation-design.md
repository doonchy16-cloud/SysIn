# SysIn V1.1 Public Foundation — Design

## Status

Owner-approved on 2026-09-08. This document records the locked public CLI direction for implementation.

## Product identity

SysIn is a Windows System Intelligence CLI and live terminal dashboard. Its core role is to observe, inspect, monitor, export, and diagnose system telemetry. SysIn is read-only by default and does not perform overclocking, undervolting, driver installation, registry cleaning, debloating, fan control, or destructive process management.

## Public CLI contract

SysIn uses a hybrid command model:

- Canonical CLI: `sysin <command> [options]`
- PowerShell convenience aliases: `SysIn -CPU`, `SysIn -GPU`, `SysIn -Version`, `SysIn -Update`, etc.

Canonical commands are the long-term compatibility surface. Convenience switches map to canonical commands.

## V1.1 command scope

V1.1 implements the public foundation and the core usable commands:

- `sysin` / `sysin overview`
- `sysin cpu`
- `sysin gpu`
- `sysin memory`
- `sysin storage`
- `sysin network`
- `sysin processes`
- `sysin sensors`
- `sysin system`
- `sysin snapshot`
- `sysin doctor`
- `sysin capabilities`
- `sysin version`
- `sysin check-update`
- `sysin update`
- `sysin config`
- `sysin help`
- `sysin about`

Convenience aliases include `-CPU`, `-GPU`, `-Memory`, `-Storage`, `-Network`, `-Processes`, `-Sensors`, `-System`, `-Snapshot`, `-Version`, `-CheckUpdate`, `-Update`, and `-Help`.

Commands from the larger locked command tree such as `record`, `report`, `rollback`, `repair`, `profile`, `theme`, `completion`, `support-bundle`, and destructive process actions are intentionally not implemented in V1.1. They must not appear as fake working commands.

## Dashboard compatibility

The V1.0 live dashboard remains the interactive default. It retains:

- 20 FPS default render target
- 20 → 10 → 5 → 1 FPS cycling
- pause/resume
- reset min/peak
- Overview, CPU, GPU, Memory, and Processes pages
- CPU, GPU, RAM, disk, network, process, uptime, and supported sensor telemetry
- graceful `N/A` for unavailable hardware metrics

Expensive providers are sampled less frequently and cached so display FPS does not imply expensive-provider polling at 20 Hz.

## Platform and installation

- Windows only for V1.1 runtime telemetry.
- Windows PowerShell 5.1+ and PowerShell 7+ are supported targets.
- Default installation is per-user and requires no administrator rights.
- Default install directory: `%LOCALAPPDATA%\Programs\SysIn`.
- Installation modifies only the current user's PATH.
- No service, daemon, scheduled task, machine-wide PATH mutation, or permanent execution-policy change.
- Existing runtime files are backed up before replacement.
- Unknown user files are never deleted by uninstall/update.

## Versioning

V1.1 version is `1.1.0` and channel is `stable`.

`sysin version`, `SysIn -Version`, `sysin --version`, and `sysin -v` report installed version and channel without launching telemetry.

## Update architecture

The public repository `doonchy16-cloud/SysIn` is the source of truth.

V1.1 uses a small public release manifest at `release/manifest.json`. The manifest contains the latest stable version, channel, minimum PowerShell version, and a list of runtime files with SHA-256 hashes and download paths.

`sysin check-update` downloads only the manifest and compares semantic versions.

`sysin update` must:

1. download the manifest over HTTPS;
2. refuse an invalid/incomplete manifest;
3. compare installed and remote versions;
4. download files into a staging directory;
5. verify every SHA-256 before installation;
6. back up current known runtime files;
7. replace only known SysIn runtime files;
8. clean staging files;
9. restore the backup if replacement fails.

V1.1 does not silently update. Normal dashboard launch may not install anything.

## Configuration

V1.1 configuration is per-user JSON under `%LOCALAPPDATA%\SysIn\config.json` and is separate from the program directory. Supported initial keys are:

- `fps` (1-20; default 20)
- `updateChannel` (`stable` only in V1.1)
- `updateCheck` (`manual` or `daily`; default `manual`)

`sysin config`, `sysin config show`, `get`, `set`, `reset`, and `path` are supported. Unknown keys or invalid values fail clearly instead of being silently accepted.

## Diagnostics and capabilities

`sysin capabilities` reports whether major telemetry providers are available, including CPU/RAM, Windows GPU counters, NVIDIA SMI, CPU temperature provider, storage/network counters, and battery availability.

`sysin doctor` verifies the SysIn install/runtime surface: Windows runtime, PowerShell version, required runtime files, user PATH registration, configuration validity, and provider availability. Doctor reports PASS/PARTIAL/FAIL per check and does not repair automatically.

## Output behavior

V1.1 prioritizes human-readable terminal output. `snapshot` is non-interactive and exits. Machine-readable JSON/CSV output is reserved for a later release unless implemented completely and tested; V1.1 must not advertise unsupported output formats.

## Safety and privacy

- No telemetry is sent to SysIn or the repository.
- Update checks contact only the public SysIn repository endpoint required to retrieve the manifest/files.
- No hidden logging.
- No machine-wide environment changes in default install.
- No fabricated sensor values.
- No destructive system-tuning behavior.

## Quality gate

V1.1 is not PASS merely because files exist. Windows CI must parse the PowerShell files and pass the automated test suite. Live hardware/dashboard behavior on real Windows hardware remains a separate verification gate after installation.
