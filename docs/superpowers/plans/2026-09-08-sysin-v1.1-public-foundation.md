# SysIn V1.1 Public Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the existing SysIn V1.0 dashboard into a public, versioned Windows CLI V1.1.0 with a hybrid command surface, per-user install, diagnostics/configuration, and a hash-verified self-update foundation.

**Architecture:** Preserve the V1.0 telemetry/rendering engine in `src/SysIn.Core.psm1`. Add a thin CLI entry point plus focused config and update modules. Root install/launcher files provide public distribution while Windows GitHub Actions runs parser, behavior, and safety tests.

**Tech Stack:** Windows PowerShell 5.1+, PowerShell 7+, CIM/WMI, Windows performance counters, NVIDIA `nvidia-smi` when present, JSON configuration, GitHub raw HTTPS distribution, Pester 5 in CI.

**Spec:** `docs/superpowers/specs/2026-09-08-sysin-v1.1-public-foundation-design.md`

## Global Constraints

- Version is exactly `1.1.0`; channel is `stable`.
- Runtime is Windows only in V1.1; CLI metadata/help/version paths must remain testable without live telemetry.
- Default install path is `%LOCALAPPDATA%\Programs\SysIn`.
- Default install scope is current user only; no admin, service, scheduled task, machine PATH, or permanent execution-policy changes.
- Existing V1.0 dashboard functionality is preserved.
- Unsupported telemetry is `N/A`, never fabricated.
- Canonical syntax is `sysin <command>`; PowerShell-style switches remain convenience aliases.
- Update downloads must stage and SHA-256 verify every runtime file before replacement.
- No license is invented.
