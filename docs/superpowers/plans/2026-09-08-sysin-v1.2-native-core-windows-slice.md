# SysIn V1.2 Native Core + Windows x64 Vertical Slice Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the first native SysIn preview as a side-by-side Windows x64 vertical slice proving universal telemetry contracts, independently scheduled supervised collectors, coherent snapshots, a purpose-built responsive Spectrum TUI, real local Overview telemetry, and basic CLI/JSON without replacing the installed V1.1 runtime.

**Architecture:** Windows collectors translate real machine data into universal typed observations. `CollectorScheduler` runs collectors independently from rendering; `CollectorSupervisor` contains faults and publishes collector-health state. `TelemetryStore` creates immutable snapshots containing devices, latest metrics, and collector health. CLI and TUI consume snapshots independently. The TUI uses a virtual-testable framebuffer/diff renderer with responsive Spectrum components. V1.1 stays untouched.

**Tech Stack:** C# 14 / .NET 10 LTS; shared libraries `net10.0`; first Windows executable/provider `net10.0-windows`; `xunit.v3` 4.0.0; `Microsoft.NET.Test.Sdk` 18.9.0; `System.Management` 10.0.12 for Windows GPU identity; built-in `System.Net.NetworkInformation`, `System.IO.DriveInfo`, `System.Text.Json`, and Windows P/Invoke for low-cost CPU/memory primitives.

**Spec:** `docs/superpowers/specs/2026-09-08-sysin-v1.2-universal-mesh-design.md`

## Global Constraints

- V1.1 PowerShell runtime, launcher, installer, release manifest, and existing PowerShell tests remain unchanged.
- Native preview runs from explicit build/publish output only; it does not replace `%LOCALAPPDATA%\Programs\SysIn` or the installed `sysin` command.
- Universal libraries target `net10.0`; `SysIn.Platform.Windows` and the first Windows `SysIn.App` executable target `net10.0-windows`.
- Nullable, implicit usings, deterministic builds, and warnings-as-errors are enabled.
- View/TUI code never calls Windows/provider APIs directly.
- Missing telemetry is explicit; zero is never a missing-data sentinel.
- Distinct GPUs remain distinct; no GPU metric is assigned by WMI/list position or inferred mapping.
- Workstream 1 guarantees GPU identity, not GPU utilization. GPU utilization is N/A until Workstream 2 introduces a provider/device mapping that is independently proven.
- Rendering and collection are independent clocks. Balanced render target is 20 FPS; measured actual FPS is separate.
- No busy-wait loops. A slow/broken collector cannot block rendering or another collector.
- No admin requirement, account, Mesh, cloud telemetry, hidden service, scheduled task, PATH mutation, migration, or destructive action occurs here.
- Overview must use available screen space and Spectrum subsystem identity; V1.1-style top-left island/dead-space behavior is HOLD.
- This workstream produces Preview evidence only; it cannot authorize Stable or a GitHub Release.

- [ ] **Step 1: Write hardware-agnostic discovery/null-state tests**

- [ ] **Step 2: Implement CPU/memory/system**

CPU uses `GetSystemTimes`; first sample Unavailable/NotApplicable, then `busy=(kernelDelta+userDelta)-idleDelta`, utilization=`clamp(100*busy/(kernelDelta+userDelta),0,100)`. Memory uses `GlobalMemoryStatusEx`. Uptime uses `Environment.TickCount64/1000.0` seconds.

- [ ] **Step 3: Implement GPU identity only**

WMI query:

```sql
SELECT PNPDeviceID, Name, DriverVersion, VideoProcessor FROM Win32_VideoController
```

Hash PNPDeviceID (or strongest stable available identity parts) into DeviceId. Keep human name/vendor/model metadata separate. Do not infer Integrated/Discrete/HighPerformance merely from vendor/name. Do not emit VRAM capacity from `Win32_VideoController.AdapterRAM`; it is not a sufficient trustworthy source for modern high-VRAM adapters. Overview treats absent `gpu.utilization` as N/A.
